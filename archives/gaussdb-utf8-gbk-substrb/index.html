【GaussDB】在UTF8的库上按GBK的字节数截取字符串

背景

在国产数据库迁移过程中，可能会有这样一个场景：源库ORACLE用的是ZHS16GBK字符集，目标库GaussDB用的是UTF8字符集，如果源库是VARCHAR2(10),且字段内容里包含汉字，那么目标库字段需要增长，假设按照常规的一个汉字在GBK占2字节，到UTF8占3个字节，也就是按原长度的1.5倍，即VARCHAR2(15)。

然而如果迁移后，国产库里产生的新数据需要回流到ORACLE，可能会存在ORACLE中长度不足的问题，比如新数据为 "咕咕嘎嘎123" ，在UTF8是15个字节，在ZHS16GBK是11个字节。

所以为了确保数据能回去，只能进行截断（别说为什么前端不控制，总会有各种各样的原因），然而如果用在UTF8库上按字节数进行截断，可能又会截多了，比如源库VARCHAR2(10) "咕咕嘎嘎啊" ，在UTF8上substrb截10个字节，会变成"咕咕嘎"+一个字节，截断尾部乱码后就只剩三个汉字了，少了两个字。

由此产生了一个需求：
在GaussDB的UTF8库里按照GBK编码的字节数实现一个类似substrb的自定义函数，输入字符串、开始位置、保留字符数，返回截取后的字符串，以确保尽可能保留ORACLE中的数据。

我的方案

create or replace function uf_gbk_substrb (input_str varchar,pos number,len number) returns varchar 
RETURNS NULL ON NULL input
IMMUTABLE
as
$$
declare
l_tmp bytea;
begin
if length(input_str)=0 then return null;
end if;
l_tmp:=convert_to(input_str::text,'GBK');
for i in 1..3 loop
begin
return convert_from(substr(l_tmp,greatest(pos-1,0),least(len-i+1,length(l_tmp))),'GBK');
exception when others then null;
end;
end loop;
RAISE EXCEPTION 'invalid byte sequence for encoding "GBK": %', l_tmp::text;
end;
$$ language plpgsql;

基本用法和普通的subtrb一样，不过我没去写反向截取（即负数入参）的逻辑。下面就是按GBK10个字节去截的效果。

gaussdb=> select uf_gbk_substrb('咕咕嘎嘎123',1,10);
 uf_gbk_substrb 
----------------
 咕咕嘎嘎12
(1 row)
gaussdb=> select uf_gbk_substrb('123咕咕嘎嘎',1,10);
 uf_gbk_substrb 
----------------
 123咕咕嘎
(1 row)
gaussdb=> select uf_gbk_substrb('咕咕嘎嘎啊',1,10);
 uf_gbk_substrb 
----------------
 咕咕嘎嘎啊
(1 row)

注意到第2个测试用例，截完后GBK占9个字节，并没有填满10个字节，是因为PG系对不完整字符的支持都不好，所以我只能尽可能保留UTF8能识别的字符，尾部的半个汉字需要截掉。

接下来逐行解释一下这个函数的设计思路

NULL ON NULL input

如果输入参数为空，则直接返回空

if length(input_str)=0 then return null;
end if;

如果输入字符串长度为0，则直接返回空（有人可能认为这个已经有了null on null input就够了，但其实null和0长度字符串是不一样的，哪怕是在A兼容模式下）

l_tmp:=convert_to(input_str::text,'GBK');

使用临时变量暂存输入字符串的GBK二进制数据

for i in 1..3 loop
begin
return convert_from(substr(l_tmp,greatest(pos-1,0),least(len-i+1,length(l_tmp))),'GBK');
exception when others then null;
end;
end loop;

对这个临时二进制变量按字节截取（注意当入参是bytea类型时，substr是按字节截取，且最小开始位置是0，而不是1）。
substr截完后还是二进制，再转回字符串。此时如果尾部存在不完整字符，则可能报错，因此尝试再少截一个字符进行重试，最多3次。

RAISE EXCEPTION 'invalid byte sequence for encoding "GBK": %', l_tmp::text;

三次都转换报错，则函数报错无效的字节序，并打印对应的GBK二进制数据。

这函数我纯手搓的，因为我经常与字符集打交道，这个逻辑对我来说算是挺简单的了。

AI会怎么做？

然后我突发奇想，如果把这个需求丢给AI ，AI会怎么做？

于是我把本文开头的背景说明直接给到了mimo-v2.5-pro，ta生成了一个逻辑比我的方案复杂得多的函数（AI生成的代码里带了parallel，GaussDB不支持，我手动删掉了）

-- ============================================================
-- gbk_substrb: 在 UTF8 数据库中按 GBK 编码字节数实现 substrb
-- 用途：GaussDB(UTF8) → Oracle(ZHS16GBK) 数据回流时的字段截断
--
-- 与 Oracle SUBSTRB 行为对齐：
--   start_pos=0  → 等效于 1
--   start_pos<0  → 从字符串末尾倒数
--   截取跨越某字符的 GBK 字节边界时，该字符被跳过（不截断半个字符）
--
-- 参数：
--   src_str    - 输入字符串（UTF8）
--   start_pos  - 起始位置（GBK 字节数，从 1 开始）
--   sub_length - 截取长度（GBK 字节数，可选，默认取到末尾）
-- ============================================================
CREATE OR REPLACE FUNCTION gbk_substrb(
    src_str    TEXT,
    start_pos  INTEGER,
    sub_length INTEGER DEFAULT NULL
)
RETURNS TEXT
LANGUAGE plpgsql
IMMUTABLE 
AS $$
DECLARE
    v_len       INTEGER;
    v_char      TEXT;
    v_cp        INTEGER;
    v_blen      INTEGER;
    v_eff_start INTEGER;
    v_real_pos  INTEGER   := 0;   -- 当前 GBK 字节位置（从 1 开始）
    v_result    TEXT      := '';
    v_begin     INTEGER   := 0;   -- 截取开始的 GBK 字节位置
    v_end       INTEGER;          -- 截取结束的 GBK 字节位置
    v_started   BOOLEAN   := FALSE;
BEGIN
    IF src_str IS NULL OR start_pos IS NULL THEN
        RETURN NULL;
    END IF;

    v_len := char_length(src_str);
    IF v_len = 0 THEN
        RETURN '';
    END IF;

    -- Oracle 行为：start_pos=0 等效于 1
    IF start_pos = 0 THEN
        v_eff_start := 1;
    ELSE
        v_eff_start := start_pos;
    END IF;

    -- 计算截取结束位置（GBK 字节数）
    IF sub_length IS NULL THEN
        v_end := 2147483647;  -- 取到末尾
    ELSE
        v_end := v_eff_start + sub_length - 1;
    END IF;

    -- 负数 start_pos：从末尾倒数
    IF v_eff_start < 0 THEN
        -- 先算出整个字符串的 GBK 字节总长
        DECLARE
            v_total INTEGER := 0;
            v_ch    TEXT;
            v_c     INTEGER;
        BEGIN
            FOR i IN 1..v_len LOOP
                v_ch := substr(src_str, i, 1);
                v_c  := ascii(v_ch);
                IF v_c <= 127 THEN
                    v_total := v_total + 1;
                ELSIF v_c BETWEEN 192 AND 223 THEN
                    v_total := v_total + 1;
                ELSE
                    v_total := v_total + 2;
                END IF;
            END LOOP;
            v_eff_start := v_total + v_eff_start + 1;
            v_end := v_eff_start + COALESCE(sub_length, 1) - 1;
        END;
    END IF;

    IF v_eff_start <= 0 THEN
        RETURN NULL;
    END IF;

    -- 遍历每个字符，按 GBK 字节数做截取
    FOR i IN 1..v_len LOOP
        v_char := substr(src_str, i, 1);
        v_cp   := ascii(v_char);

        -- 计算该字符在 GBK 编码中的字节数
        IF v_cp <= 127 THEN
            -- ASCII（含英文、数字、符号）
            v_blen := 1;
        ELSIF v_cp BETWEEN 192 AND 223 THEN
            -- U+0080 ~ U+07FF：Latin 扩展、希腊语、阿拉伯语等
            -- GBK 通常 1 字节（直通映射或 ?）
            v_blen := 1;
        ELSE
            -- U+0800+：CJK 等，在 GBK 中占 2 字节
            v_blen := 2;
        END IF;

        v_real_pos := v_real_pos + v_blen;

        -- 定位截取起始点
        IF NOT v_started AND v_real_pos >= v_eff_start THEN
            v_started := TRUE;
            v_begin   := v_real_pos - v_blen + 1;
        END IF;

        -- 截取结束（字符跨越 end 边界则跳过）
        IF v_started AND v_real_pos > v_end THEN
            EXIT;
        END IF;

        IF v_started THEN
            v_result := v_result || v_char;
        END IF;
    END LOOP;

    RETURN v_result;
END;
$$;

COMMENT ON FUNCTION gbk_substrb(TEXT, INTEGER, INTEGER)
    IS '在 UTF8 库中按 GBK 字节数截取字符串，用于 GaussDB→Oracle(ZHS16GBK) 数据回流截断';

大概的逻辑就是从前到后逐字符遍历一个一个字符截取，根据每一个字符的ascii码大小范围判断它是1个字节还是多个字节的（多字节都按2字节算），视为GBK字节长度，然后把一个一个字符拼起来，拼的同时GBK字节数也累加，直到计数器达到目标长度就跳出循环，返回拼接的字符串。

AI的额外启发

AI其实还同时生成了另一个计算gbk字节数的函数

-- ============================================================
-- gbk_bytelen: 计算字符串在 GBK 编码下的字节长度
-- 用途：截断前预判是否需要截断
-- ============================================================
CREATE OR REPLACE FUNCTION gbk_bytelen(src_str TEXT)
RETURNS INTEGER
LANGUAGE plpgsql
IMMUTABLE PARALLEL SAFE
AS $$
DECLARE
    v_len    INTEGER;
    v_total  INTEGER := 0;
    v_char   TEXT;
    v_cp     INTEGER;
BEGIN
    IF src_str IS NULL THEN
        RETURN NULL;
    END IF;

    v_len := char_length(src_str);
    FOR i IN 1..v_len LOOP
        v_char := substr(src_str, i, 1);
        v_cp   := ascii(v_char);
        IF v_cp <= 127 THEN
            v_total := v_total + 1;
        ELSIF v_cp BETWEEN 192 AND 223 THEN
            v_total := v_total + 1;
        ELSE
            v_total := v_total + 2;
        END IF;
    END LOOP;

    RETURN v_total;
END;
$$;

COMMENT ON FUNCTION gbk_bytelen(TEXT)
    IS '计算字符串在 GBK 编码下的字节数（ASCII=1, CJK=2）';

这个可以放到数据入库的前置校验逻辑中去，这样库里的数据就不需要再截断了。

另外，我也尝试了清空所有上下文，只给AI一句最简单的指令，看看ta能生成什么

"写一个GaussDB的自定义函数，在UTF8的库上按GBK的字节数截取字符串"

然后AI给了我3个方案

-- 方法1：PL/pgSQL 函数（推荐，兼容性好）
CREATE OR REPLACE FUNCTION gbk_substr(p_str TEXT, p_max_bytes INTEGER)
RETURNS TEXT
LANGUAGE plpgsql
IMMUTABLE
AS $$
DECLARE
    v_result TEXT := '';
    v_current_bytes INTEGER := 0;
    v_char TEXT;
    v_char_bytes INTEGER;
    v_len INTEGER;
    v_i INTEGER;
BEGIN
    -- 参数校验
    IF p_str IS NULL OR p_max_bytes <= 0 THEN
        RETURN '';
    END IF;

    v_len := length(p_str);

    FOR v_i IN 1..v_len LOOP
        v_char := substr(p_str, v_i, 1);

        -- 计算该字符在 GBK 编码下的字节数
        -- ASCII 字符 (0-127) 在 GBK 中占 1 字节
        -- 中文字符在 GBK 中占 2 字节
        IF ascii(v_char) <= 127 THEN
            v_char_bytes := 1;
        ELSE
            -- 非 ASCII 字符（中文等）在 GBK 中占 2 字节
            v_char_bytes := 2;
        END IF;

        -- 检查是否超出限制
        IF v_current_bytes + v_char_bytes > p_max_bytes THEN
            EXIT;
        END IF;

        v_current_bytes := v_current_bytes + v_char_bytes;
        v_result := v_result || v_char;
    END LOOP;

    RETURN v_result;
END;
$$;

COMMENT ON FUNCTION gbk_substr(TEXT, INTEGER) IS
'在 UTF8 数据库上按 GBK 字节数截取字符串。
参数：
  p_str - 输入字符串（UTF8 编码）
  p_max_bytes - 最大 GBK 字节数
返回：截取后的字符串，确保转为 GBK 后字节数不超过 p_max_bytes
示例：SELECT gbk_substr('你好世界Hello', 8);  -- 返回 "你好" (2*2=4字节) 或 "你好H" (4+1=5字节)';

-- 测试用例
-- SELECT gbk_substr('你好世界Hello', 8);   -- 预期：你好He (2+2+2+1+1=8字节)
-- SELECT gbk_substr('你好世界', 5);        -- 预期：你好 (4字节，再加"世"会超)
-- SELECT gbk_substr('Hello', 3);           -- 预期：Hel
-- SELECT gbk_substr(NULL, 10);             -- 预期：空字符串
-- SELECT gbk_substr('abc', 0);             -- 预期：空字符串


-- 方法2：SQL 函数（更简洁，但依赖 ascii() 函数可用性）
-- 如果 GaussDB 支持 ascii() 函数，可以用这个更简洁的版本
CREATE OR REPLACE FUNCTION gbk_substr_sql(p_str TEXT, p_max_bytes INTEGER)
RETURNS TEXT
LANGUAGE sql
IMMUTABLE
AS $$
    WITH chars AS (
        SELECT
            c,
            CASE
                WHEN ascii(c) <= 127 THEN 1
                ELSE 2
            END AS byte_len,
            ROW_NUMBER() OVER () AS rn
        FROM unnest(string_to_array(p_str, NULL)) AS c
    ),
    cumulative AS (
        SELECT
            c,
            byte_len,
            SUM(byte_len) OVER (ORDER BY rn) AS cumulative_bytes
        FROM chars
    )
    SELECT COALESCE(string_agg(c, ORDER BY cumulative_bytes), '')
    FROM cumulative
    WHERE cumulative_bytes <= p_max_bytes;
$$;

COMMENT ON FUNCTION gbk_substr_sql(TEXT, INTEGER) IS 'SQL 版本的 GBK 字节截取函数（更简洁）';


-- 方法3：如果需要处理 GBK 编码中的特殊字符（如一些罕用字可能是 4 字节）
-- 使用 convert_to 函数进行精确计算（需要 PostgreSQL 9.x+ 或 GaussDB 支持）
CREATE OR REPLACE FUNCTION gbk_substr_exact(p_str TEXT, p_max_bytes INTEGER)
RETURNS TEXT
LANGUAGE plpgsql
IMMUTABLE
AS $$
DECLARE
    v_result TEXT := '';
    v_current_bytes INTEGER := 0;
    v_char TEXT;
    v_char_bytes INTEGER;
    v_len INTEGER;
    v_i INTEGER;
    v_gbk_bytes BYTEA;
BEGIN
    IF p_str IS NULL OR p_max_bytes <= 0 THEN
        RETURN '';
    END IF;

    v_len := length(p_str);

    FOR v_i IN 1..v_len LOOP
        v_char := substr(p_str, v_i, 1);

        -- 使用 convert_to 精确计算 GBK 字节数
        BEGIN
            v_gbk_bytes := convert_to(v_char, 'GBK');
            v_char_bytes := length(v_gbk_bytes);
        EXCEPTION WHEN OTHERS THEN
            -- 转换失败时按 2 字节估算
            v_char_bytes := 2;
        END;

        IF v_current_bytes + v_char_bytes > p_max_bytes THEN
            EXIT;
        END IF;

        v_current_bytes := v_current_bytes + v_char_bytes;
        v_result := v_result || v_char;
    END LOOP;

    RETURN v_result;
END;
$$;

COMMENT ON FUNCTION gbk_substr_exact(TEXT, INTEGER) IS '精确版本：使用 convert_to 计算 GBK 字节数（性能较低但最准确）';

三个方案都是遍历字符，然后拼接，但区别是：

  • 第一个方案和AI前面的方案原理一样，循环截取，然后按ascii大小判断GBK长度
  • 第二个方案是SQL语言函数，将字符串按每个字符切分转成一个数组，然后再按ascii大小计算字节长度
  • 第三个方案考虑了生僻字，使用了内置函数convert_to来精确识别字节数

总结

不是为自己找补，我的方案和AI第一版的方案相比，虽然AI的性能更好，但是如果需要把方案给到一个对字符集不是很理解的开发人员，考虑到函数可能还存在一些边界场景的BUG（比如生僻字），我可能仍然还会提供我自己的方案。因为AI的方案代码量稍大，有些特殊场景也没有考虑，我的方案里是有数据库自己的内置函数来进行未知情况的兜底。

不过，如果能有真实大量的数据测试一下AI这个函数，识别到可能的边界场景，让AI来完善这个函数的处理，并且自动化进行性能测试分析和调整，这可能是更符合AI-AGENT时代的做法了。

另一方面，不能忽视的是，虽然AI这次写得挺好，但前提是我能准确地描述这个问题，即本文中的背景说明，这一段并非我收到的原始描述，而是我根据开发人员的无法准确描述的未知担忧逐步拆解分析出来的。AI的使用者依旧需要具有清晰的逻辑思考能力以及语言表达能力，才能让AI完成想让ta完成的事。

但是，描述得越详细，有时候也可能会扼杀AI的创造力，比如我第二次给AI提的一句话需求的回答中，其实AI反而考虑到了前面长提示词的回答没有考虑到的生僻字场景。
